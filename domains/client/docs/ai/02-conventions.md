# Соглашения Dart/Flutter в проекте

## Именование файлов

- Имена файлов — `snake_case.dart`, совпадают с именем основного класса в файле: `task_list.dart` → `TaskListBloc`/`TaskListState` (`lib/state/task_list/task_list.dart:6, 79`), `domain_list.dart` → `DomainListBloc` (`lib/state/domain_list/domain_list.dart:6`), `contact_list.dart` → `ContactListBloc` (`lib/state/contact_list/contact_list.dart:6`).
- Файлы страниц называются по маршруту/действию: `login_user_create.dart`, `login_user_existing.dart`, `login_user_save_credentials.dart` — все в `lib/ui/pages/`.
- Файлы с приватной реализацией слоя лежат в подпапке с именем технологии: `lib/local_storage/isar/isar_storage.dart`, `lib/local_storage/hive/hive_storage.dart`, `lib/remote_storage/firebase_realtime_database.dart`.
- Сгенерированные файлы имеют суффикс `.g.dart` и то же базовое имя: `isar_storage.g.dart` рядом с `isar_storage.dart` (`lib/local_storage/isar/isar_storage.g.dart`).
- Библиотечные файлы-агрегаторы называются по имени папки и объявляют `library <name>;`: `lib/repository/repository.dart:1` (`library repository;`), `lib/state/state.dart:1` (`library state;`), `lib/local_storage/local_storage.dart:1` (`library local_storage;`).
- Файлы моделей, объединённых в одну логическую сущность через `part of`, называются по имени модели в единственном числе: `user.dart`, `domain.dart`, `task.dart`, `registry.dart` — все в `lib/repository/models/`, подключены как `part 'user.dart';` в `lib/repository/models/models.dart:10-13`.

## Именование классов

- Классы — `PascalCase`. Виджет-страница называется `<Feature>Page`: `TaskListPage` (`lib/ui/pages/task_list.dart:11`), `DomainListPage` (`lib/ui/pages/domain_list.dart:8`), `ContactListPage` (`lib/ui/pages/contact_list.dart:9`), `LoginPage` (`lib/ui/pages/login.dart:22`).
- Для каждой страницы с BLoC рядом объявлен класс `<Feature>View`, отделяющий `BlocProvider` от собственно вёрстки: `TaskListView` (`lib/ui/pages/task_list.dart:34`), `DomainListView` (`lib/ui/pages/domain_list.dart:29`), `ContactListView` (`lib/ui/pages/contact_list.dart:30`), `HomeView` (`lib/ui/pages/home.dart:28`), `UnknownView` (`lib/ui/pages/unknown_page.dart:25`).
- BLoC называется `<Feature>Bloc`, состояние — `<Feature>State`, события — `<Feature>Event` (`sealed class`) с конкретными событиями `<Action>Requested`: `TaskListBloc`/`TaskListState`/`TaskEvent`/`TaskCompletionRequested`/`TaskAddRequested`/`TaskSubmitionRequested`/`TaskChangingRequested` (`lib/state/task_list/task_list.dart:6, 79, 96, 107, 116, 120, 129`); аналогично `DomainListBloc`/`DomainEvent`/`DomainCreationRequested`/`DomainDeletionRequested`/`DomainChangingRequested`/`DomainSyncRequested` (`lib/state/domain_list/domain_list.dart:6, 120, 131, 138, 145, 152`); `ContactListBloc`/`ContactEvent`/`ContactInvitationRequested`/`ContactHandshakeRequested`/`ContactCreateUserProjectionRequested`/`ContactUserSyncRequested`/`ContactDomainSyncRequested` (`lib/state/contact_list/contact_list.dart:6, 127, 139, 159, 169, 184, 192`).
- Каждый `<Feature>Event` имеет ровно одно событие инициализации `<Feature>ListStateInitRequested`: `TaskListStateInitRequested` (`lib/state/task_list/task_list.dart:103`), `DomainListStateInitRequested` (`lib/state/domain_list/domain_list.dart:127`), `ContactListStateInitRequested` (`lib/state/contact_list/contact_list.dart:134`).
- Классы-исключения называются `<Reason>` и реализуют `implements Exception` с полями `message`/`statusCode`: `RebaseCollision implements Exception` (`lib/repository/repository/repository.dart:22`), `RemoteStorageWriteCollision implements Exception` (`lib/remote_storage/remote_storage.dart:8`).
- Абстракции хранилищ называются по роли без префикса `I`: `abstract class LocalStorage` (`lib/local_storage/local_storage.dart:9`), `abstract class RemoteStorage` (`lib/remote_storage/remote_storage.dart:18`), их реализации — `<Technology>Storage`: `IsarStorage` (`lib/local_storage/isar/isar_storage.dart:90`), `HiveStorage` (`lib/local_storage/hive/hive_storage.dart:7`), `FirebaseStorage` (`lib/remote_storage/firebase_realtime_database.dart:8`).

## Структура виджетов

- Каждая страница построена по паттерну «внешний `<Feature>Page` создаёт `BlocProvider`, внутренний `<Feature>View` содержит `BlocBuilder`»: `DomainListPage.build` возвращает `BlocProvider(create: (context) => DomainListBloc(repository: repository), child: const DomainListView())` (`lib/ui/pages/domain_list.dart:20-26`), `DomainListView.build` оборачивает в ещё один `BlocProvider<DomainListBloc>` с добавлением `DomainListStateInitRequested()` и рендерит через `BlocBuilder<DomainListBloc, DomainListState>` (`lib/ui/pages/domain_list.dart:39-43`). Тот же паттерн — `TaskListPage`/`TaskListView` (`lib/ui/pages/task_list.dart:27-46`) и `ContactListPage`/`ContactListView` (`lib/ui/pages/contact_list.dart:23-42`).
- Страницы без BLoC — простой `StatelessWidget` без внутреннего `View`-класса, если состояние не нужно: `LoginPage` (`lib/ui/pages/login.dart:22`), `SaveUserCredentialsPage` (`lib/ui/pages/login_user_save_credentials.dart:6`), `LoginUserExistingPage` (`lib/ui/pages/login_user_existing.dart:7`).
- Страницы с локальным (не BLoC) изменяемым состоянием используют `StatefulWidget` + `State<StatefulWidget>` с суффиксом `State`: `CreateUserPage`/`CreateUserPageState` (`lib/ui/pages/login_user_create.dart:6, 15`), состояние обновляется через `setState(() { ... })` (`lib/ui/pages/login_user_create.dart:40-42, 49-51`).
- Конструктор страницы принимает `Repository repository` первым позиционным параметром, остальное — именованные опциональные параметры: `const TaskListPage(this.repository, {super.key, this.id})` (`lib/ui/pages/task_list.dart:15-21`), `const HomePage(this.repository, {super.key, this.title})` (`lib/ui/pages/home.dart:12-18`), `const UnknownPage(this.repository, {super.key, this.title})` (`lib/ui/pages/unknown_page.dart:9-15`).
- `routeName` объявлен как `static const routeName = '/...'` прямо в классе страницы: `SplashScreen.routeName = '/splash'` (`lib/ui/pages/splash_screen.dart:9`), `TaskListPage.routeName = '/tasklist'` (`lib/ui/pages/task_list.dart:13`), `ContactListPage.routeName = '/contacts'` (`lib/ui/pages/contact_list.dart:10`).
- Внутри `build()` в начале извлекаются короткие локальные алиасы контекста: `final l = AppLocalizations.of(context);`, `final n = Navigator.of(context);`, `final t = Theme.of(context);`, `final b = BlocProvider.of<...Bloc>(context);` — повторяется в `lib/ui/pages/task_list.dart:39-41`, `lib/ui/pages/domain_list.dart:34-37`, `lib/ui/pages/contact_list.dart:35-38`, `lib/ui/pages/home.dart:40-42`.
- Переиспользуемые виджеты выносятся в `lib/ui/widgets/` и принимают поведение через `ValueChanged<T>`/`VoidCallback` — `TaskListTile` с `onValueChanged`, `onTitleSubmitted`, `onTitleChanged`, `onTitleEditingComplete` (`lib/ui/widgets/task_list_tile.dart:3-25`).

## Обработка ошибок

- В `main()` инициализация оборачивается в `try { ... } catch (error) { print(error); }` без пробрасывания дальше — `lib/main.dart:10-23`.
- Кастомные исключения хранилищ несут код ошибки: `RemoteStorageWriteCollision(this.message, this.statusCode)` — `lib/remote_storage/remote_storage.dart:8-16`; бросается из `FirebaseStorage.saveItems` при `FirebaseException` с `e.code == 'permission-denied'`: `throw RemoteStorageWriteCollision(e.code, 0);` — `lib/remote_storage/firebase_realtime_database.dart:139-144`.
- `Repository.syncWithRemoteStorage` перехватывает именно `RemoteStorageWriteCollision` для повторного ребейза транзакции: `on RemoteStorageWriteCollision catch (e) { isRemoteRegistriesActual = false; ... }` — `lib/repository/repository/repository.dart:624-629`.
- Отсутствие обязательного локального пользователя выражается через `throw StateError(...)` в геттере/сеттере `Repository.me`: `throw StateError('Local user is unknown: $myId');`, `throw StateError('No such user in local storage: $myId');` — `lib/repository/repository/repository.dart:454-462`.
- Отсутствие входных данных для операции выражается через `throw Exception('...')`: `throw Exception('Cant create user for remote storages while local user not initialized');` (`lib/repository/repository/repository.dart:187`), `throw Exception('User secret for remote storage ${storage.key} is not specified');` (`lib/repository/repository/repository.dart:196`).
- `Repository.createUserRemoteStorages` перехватывает `on Exception catch (e)`, логирует и продолжает цикл по остальным хранилищам, устанавливая `success = false` — `lib/repository/repository/repository.dart:201-207`.
- Ошибки, не влияющие на бизнес-логику (недоступный элемент, недостающий параметр настроек), не бросаются, а логируются через `print(...)` и функция возвращает управление без исключения: `print('No parameter $instanceFieldName is specified for ${storage.key}');` в `initRemoteStorages`/`authRemoteStorages` (`lib/repository/repository/repository.dart:168, 180, 227`).
- В `FirebaseStorage.getItem` сетевые ошибки перехватываются широким `catch (error) { print(error); }` без пробрасывания — `lib/remote_storage/firebase_realtime_database.dart:44-53`.
- Ошибки логина в UI не бросаются, а просто логируются и форма остаётся на месте: `print('login $userId failed');` в трёх местах `LoginUserExistingPage` — `lib/ui/pages/login_user_existing.dart:39, 63, 83`.

## Логирование

- Единственный механизм логирования — `print(...)`, отдельного логгера (`logger`, `dart:developer log`) в проекте нет.
- Диагностические сообщения по слушателям синхронизации имеют фиксированный формат `'<BlocName>: localChanges=$localChanges, remoteChanges=$remoteChanges'`: `lib/state/domain_list/domain_list.dart:48`, `lib/state/contact_list/contact_list.dart:51`.
- Сообщения об ошибках Firebase имеют формат `'Firebase Error: ${e.code} — ${e.message}'` и `'Unknown Firebase Error: $e'` — `lib/remote_storage/firebase_realtime_database.dart:176, 179`.
- Отладочные `print` внутри `Repository` описывают предметную область на русском: `'Merge conflict detected for items: $localItems'`, `'Remote items: $remoteItems'` (`lib/repository/repository/repository.dart:261-262`), `'Access denied for items: $items'` (`lib/repository/repository/repository.dart:266`), `'No domain found for ${entry.value.runtimeType} ${entry.key}'` (`lib/repository/repository/repository.dart:643`).

## Работа с асинхронностью

- Методы работы с хранилищами и репозиторием — `Future<T>`/`async`/`await`: `Future<void> init() async {...}` (`lib/repository/repository/repository.dart:145-156`), `Future<void> saveModel(...) async {...}` (`lib/repository/repository/repository.dart:396-404`).
- Периодическая фоновая синхронизация реализована через собственный класс `Timer` на основе `Stream.periodic`, а не через `dart:async Timer`: `class Timer { ... Stream<int>? _timer; StreamSubscription<int>? _timerSubscription; ... }` — `lib/repository/repository/repository.dart:33-79`; запускается как `_sync = Timer(_delayedSync); _sync.start();` (`lib/repository/repository/repository.dart:152-153`) и продлевается через `_sync.postpone()` при каждой записи (`lib/repository/repository/repository.dart:403, 412, 429, 441, 449`).
- В UI асинхронные обработчики `onPressed`/`onSubmitted` объявлены как `async` лямбды, ожидающие результат через `await showModalBottomSheet(...)` перед переходом на следующий экран: `User blankUser = User(name: ''); bool? isPerformed = await showModalBottomSheet(...);` — `lib/ui/pages/login.dart:40-47`.
- Синхронный API у `LocalStorage`/`Repository` (`getModel`, `getItem`, `me`) не асинхронный, в отличие от `RemoteStorage`/`Repository.syncWithRemoteStorage`, которые всегда `Future`: сравните `T? getModel<T>(String modelId, [int? subscriberId])` (`lib/repository/repository/repository.dart:406-414`, без `async`) и `Future<int> syncWithRemoteStorage(...)` (`lib/repository/repository/repository.dart:566`).
- Подписка на изменения удалённого хранилища сделана через `Stream`: `database.child('models/${ids[0]}').onChildChanged.listen((event) { ... })` в `FirebaseStorage.getItems` — `lib/remote_storage/firebase_realtime_database.dart:62-70`.
- Callback-подписки на синхронизацию репозитория используют обычные `typedef`, не `Stream`: `typedef SyncListener = void Function(String id, dynamic syncedItem);`, `typedef MergeConflictListener = void Function(...)`, регистрируются через `addSyncListener(...)` и снимаются через `removeSyncListener(...)` — `lib/repository/repository/repository.dart:15-19, 233-254`; пример снятия подписки при закрытии BLoC — `_repo.removeSyncListener(listenerId)` в `ContactListBloc.close()` (`lib/state/contact_list/contact_list.dart:23-27`).
